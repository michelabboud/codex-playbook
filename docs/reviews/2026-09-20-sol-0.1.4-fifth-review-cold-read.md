### Informational observations

1. **The residual criterion is legitimate, with a narrow interpretation.** “Belongs to a new batch” is a conservative default for genuinely unnamed work. It does not override a specific sentence or worked row, and it does not turn a recorded finding’s fix into a new batch: that case is expressly attached to the batch being repaired. An unnamed state safely resolved this way is a candidate for a later worked row, not a publication blocker.

2. **The residual does not deadlock a line at three.** A recorded blocker may still receive the changes necessary to fix it, and its focused review can run without admitting a fourth batch. If that focused review finds another defect, the new finding is validated and recorded like any other finding, its necessary fix remains inside the same repair exception, and another focused review follows. The process has no arbitrary retry cap, but it has a permitted progress step at every iteration; recurring real findings are not a policy deadlock.

3. **The focused-fix review has an identifiable validator.** Rule 3.5 says it is validated “like any other,” while rules 3.1 and 3.3 assign validation to the coordinator and require source re-checking. The depth is the depth of the review that found the defect. The pinned target plus enumerated fix commits keeps the review input stable without moving the original target.

4. **Ad-hoc batches do not provide a textual route around planned boundaries.** The exception is limited to authorized work that needs no plan. Planned work opens the batch allocated by the plan; if an existing batch is open, an authorized unplanned hotfix or docs correction joins that open batch rather than creating a parallel batch. Row 18 correctly covers zero through two carried unruled batches, an existing open batch, and the ceiling of three.

5. **The line/worktree distinction is operationally decidable.** Dispatch provenance decides it: a task worktree returns to the line and open batch from which it was dispatched; a separately admitted line inherits the carried set and opens its own new batch. The merge union and “only closed work merges” constraints preserve the ceiling, so fan-out task worktrees do not create a merge-back bypass.

6. **Row 12 agrees with both landing admission and the gate.** The docs fix lands in an admitted batch on a non-candidate line, owes ordinary review, and cannot change the frozen candidate without restarting candidate checks and review.

7. **Rows 1–6, 8, 10, and 11 remain correct under open-inclusive counting.** The older “closed batches” admission equivalence is absent from both operative rule targets. The rows that say “closed” describe their worked state rather than redefine the counted set.

8. **The changed test is directionally justified but not limited to moving two phrases.** Besides moving `a new batch starts only while at most two closed batches are unruled` and `Nothing lands on a line outside a batch` into the forbidden list, the delta expands the canonical table from 16 to 20 rows, adds four positive wording requirements, and forbids the stale `ceiling of two`. Those changes match the rule repair. The wording checks search the whole review file rather than the extracted rule 3.5 block; the target presently contains every phrase in rule 3.5, so this is test-hardening information rather than a current false green.
